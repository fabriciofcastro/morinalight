# Bug Fixes - 2025-11-26

## 1. ✅ API Port Configuration
**Issue:** Frontend was connecting to wrong backend port  
**Error:** `Contexto de tenant não disponível na requisição`  
**Root Cause:** Frontend API client defaulted to port 3001, but backend runs on 3333  
**Fix:** Updated `apps/web/src/lib/api/base.ts` line 3:
```typescript
const API_BASE_URL = process.env.NEXT_PUBLIC_API_URL || 'http://localhost:3333';
```

## 2. ✅ Organization Header Mismatch
**Issue:** Backend rejecting company-settings requests  
**Error:** `Contexto de tenant não disponível na requisição` (500 error)  
**Root Cause:** Next.js API route using `x-org-id` header, but backend expects `x-organization-id`  
**Fix:** Updated `apps/web/src/app/api/company-settings/route.ts`:
- Line 54: `request?.headers.get("x-organization-id")`
- Line 92: `"x-organization-id": orgId`
- Line 156: `"x-organization-id": orgId`

## 3. ✅ WebSocket Connection Errors
**Issue:** Console flooded with WebSocket connection errors  
**Error:** `[RealtimeNotifications] Erro na conexão`  
**Root Cause:** WebSocket server not configured, but client trying to connect  
**Fixes:**
1. Changed error logging from `console.error` to `console.warn` in `use-realtime-notifications.ts`
2. Disabled `RealtimeNotificationsProvider` in `connection-providers.tsx` (commented out)

## Impact
- ✅ Frontend now correctly communicates with backend on port 3333
- ✅ Organization context properly passed to backend
- ✅ Console errors reduced to warnings for non-critical features
- ✅ Application fully functional for authenticated users

- The `x-organization-id` header is automatically injected by the API client for authenticated requests
